# カラー設計

## 方針

Notionのウォームグレーを参考にしつつ、日本語 + システムフォント環境に最適化した独自のカラーシステム。
「なんとなくNotionっぽい」ではなく、各値にWCAGコントラスト比の根拠を持つ。

## 設計原則

### 1. 背景は純白、暖かさはテキストとサーフェスで出す

Notionの分析で得た知見:

| 要素 | Notion | my-ui |
|------|--------|-------|
| 背景 | `#ffffff`（純白） | `#ffffff`（純白） |
| テキスト | `#37352F`（暖色グレー、12.3:1） | `#1c1917`（暗い暖色、17.5:1） |
| サイドバー/セカンダリ | `#F7F6F3`（暖白、1.08:1） | `#f3f2f0`（暖白、1.10:1） |
| ボーダー | `#E9E9E7`（1.22:1） | `#e6e4e1`（1.25:1） |

Notionは背景が純白で、ウォームな印象はテキスト色とサイドバー色で出している。my-uiも同じ戦略を採用。

### 2. テキスト色がNotionより暗い理由

Notionは `#37352F`（コントラスト 12.3:1）だが、my-uiは `#1c1917`（17.5:1）を採用。

**理由: 日本語のシステムフォント(Hiragino Sans)のウェイト制約**

Notionの暖色テキスト `#37352F` を適用して検証したところ、テキストが「細く」見える問題が発生した。原因:

- Hiragino Sans は W3(~400) と W6(~600) しかなく、中間ウェイトがない
- コントラストが下がると、W3 の細さが目立つ
- Notionは独自フォントを使っており、同じ問題が起きない

font-weight: 500〜560 で補正を試みたが、Hiragino Sans では全て W3 で描画され、600 で急に W6 にジャンプするため中間が取れなかった。

Noto Sans JP（100〜900対応）の導入も検討したが、YAGNI判断で見送り。将来導入する場合はテキスト色を明るくする余地がある。

### 3. WCAG AA準拠を全テキストペアで遵守

14px の `text-ui` を使うため、通常テキストの基準 4.5:1 を全ペアで満たす。

## カラートークン（ライトモード）

| トークン | 値 | コントラスト (vs #ffffff) | 用途 |
|----------|-----|------------------------|------|
| background | `#ffffff` | - | ページ背景 |
| foreground | `#1c1917` | 17.5:1 | 本文テキスト |
| primary | `#1c1917` | 17.5:1 | プライマリボタン背景（foregroundと統一） |
| primary-foreground | `#ffffff` | - | プライマリボタン文字 |
| secondary | `#f3f2f0` | 1.10:1 | セカンダリ面（サイドバー等） |
| secondary-foreground | `#1c1917` | - | セカンダリ面のテキスト |
| muted | `#f3f2f0` | - | ミュート背景 |
| muted-foreground | `#75726e` | 4.8:1 | 補助テキスト。14pxでAA合格 |
| accent | `#f3f2f0` | - | アクセント面 |
| accent-foreground | `#1c1917` | - | アクセント面のテキスト |
| destructive | `#c4431a` | 4.8:1 (vs白文字) | 破壊アクション |
| destructive-foreground | `#ffffff` | - | 破壊ボタン文字 |
| border | `#e6e4e1` | 1.25:1 | ボーダー（Notion 1.22:1 同水準、意図的に控えめ） |
| input | `#e6e4e1` | - | 入力フィールドのボーダー |
| ring | `#1c1917` | - | フォーカスリング |

### primary = foreground の根拠

ボタン背景とテキストを同じ色にしている理由:
- **面積効果**: 同じ色でもボタン（大面積）はテキスト（小面積）より明るく知覚される
- Notionも同様にテキスト色≒ボタン色
- トークンが減りシステムがシンプルになる

### ボーダーの控えめさの根拠

背景とボーダーのコントラスト 1.25:1 はWCAG非テキスト要素の推奨(3:1)を大きく下回るが、これは意図的。
Notionも 1.22:1 で同水準。カードやセクションの区切りは「はっきり分ける」より「うっすら存在する」方がミニマムな印象になる。

## 暖かさの数値指標 (R-B差)

R値とB値の差が大きいほどウォーム。

| 要素 | Notion | my-ui |
|------|--------|-------|
| テキスト | R-B=8 | R-B=5 |
| ボーダー | R-B=2 | R-B=5 |
| セカンダリ | R-B=4 | R-B=3 |

my-uiはNotionほどテキストに暖かさを集中させず、ボーダーにも分散している。テキスト色が暗い分、暖色のR-B差が知覚的に弱まるが、セカンダリ面やボーダーが補完する。

## 検討して採用しなかったもの

### テキスト色 #33312b（Notion寄りの暖色）

コントラスト 13.0:1 で十分だが、Hiragino Sans W3 との組み合わせで「細く見える」問題が発生。font-weight 500〜560 での補正はHiragino Sansの固定ウェイト(W3/W6のみ)により不可能。

### Noto Sans JP の導入

500ウェイトが使えるようになり、テキスト色を明るくできる。ただし1ページあたり100〜300KBのフォント読み込みが発生。現時点ではYAGNI判断で見送り。将来のオプションとして残す。

### warmth切り替え機能

背景色の暖かさレベルを切り替える機能を実装していたが、「背景は純白、暖かさはテキストで」の方針に移行したため削除。
